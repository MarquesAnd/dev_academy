Módulo 1 · Lição 1 de 4

💓 O segredo de todo jogo: o loop

Do Pong ao jogo mais moderno do mundo, TODOS são o mesmo animal: um loop infinito (controlado!) que, 60 vezes por segundo, faz duas coisas:

o coração, em pseudocódigo
enquanto (oJogoEstiverAberto) {
    atualizar();   // 1. mover tudo: física, inimigos, cliques (a LÓGICA)
    desenhar();    // 2. pintar o quadro na tela (a IMAGEM)
}

Cada volta é um frame. 60 frames por segundo = a ilusão de movimento, igualzinho ao cinema. Quando um jogo "roda a 60fps", é ISTO: o loop dando 60 voltas por segundo. Quando "trava", é o loop demorando demais numa volta.

No loopQuem fazNeste curso
atualizar()A LÓGICA do jogo: posições, colisões, pontosVOCÊ escreve, em Java 💪
desenhar()Pintar o quadroVocê desenha o herói; o palco pinta o mundo
o loop em si + tecladoA infraestruturaA engine da Academy (pronta, você vai LER o código dela)
✱
É exatamente assim na indústria: devs de gameplay escrevem a LÓGICA em cima de uma engine (Unity, Godot, Unreal) que cuida de loop, tela e input. Você vai trabalhar do jeito profissional desde a missão 1 — só que entendendo o que a engine faz por baixo, porque a nossa é pequena e aberta.

💡 As coordenadas do palco

🗺️ O mundo é uma String: os mapas de tiles

Como se guarda uma fase inteira? Nos clássicos (e aqui): o mundo é uma GRADE de blocos de 32px — e a fase é literalmente um texto, um caractere por bloco:

uma fase de verdade deste curso
"                          F  "
"P         C    E        ###  "
"#####   #####################"

#  = bloco sólido      C = moeda       E = inimigo
P  = onde o herói nasce (spawn)        F = a bandeira do fim
espaço = ar (repare no BURACO entre os dois grupos de #!)

A engine lê esse texto com um loop aninhado (linha por linha, coluna por coluna — o padrão que você dominou no Java Completo!) e monta o mundo: cada # vira um bloco em x = coluna × 32, y = linha × 32.

💡 Por que os profissionais amam isso
Fase como texto = criar fases virou EDITAR TEXTO. Sem ferramenta, sem banco de dados: apaga um #, nasce um buraco. No Módulo 8, você desenha a SUA fase assim. (Jogos comerciais usam a mesmíssima ideia, só que com editores visuais que geram esses dados.)

🐣 A classe Heroi: a ficha do personagem

Todo personagem de todo jogo é, no fundo, uma classe com estado. A nossa ficha oficial — repare como cada campo responde uma pergunta do jogo:

a anatomia do herói
class Heroi {
    double x;  double y;       // ONDE ele está
    double vx; double vy;     // PARA ONDE está indo (velocidades)
    boolean noChao;           // está pisando em algo? (o pulo depende disso!)
    int pontos; int vidas;   // o placar da aventura

    Heroi(double x, double y) { ... }   // nasce no spawn do mapa
    void atualizar(Teclas t) { ... }    // chamado 60x/segundo: a LÓGICA

A separação posição (x, y) vs velocidade (vx, vy) é A decisão de design da física de jogos: as forças mexem na VELOCIDADE; a velocidade mexe na POSIÇÃO. Todo o resto do curso é consequência dessa frase — releia-a.

🎛️ Game feel: por que constantes, e não números soltos

Repare: você escreveu Fisica.VELOCIDADE, não 3. Isso tem nome — tuning (afinação). O "gostinho" de um jogo (pesado? flutuante? nervoso?) mora nesses poucos números, e mantê-los num lugar só permite afinar o jogo inteiro mexendo em uma linha:

ConstanteValor da casaSe aumentar...
VELOCIDADE3Herói apressado, controle mais "escorregadio"
GRAVIDADE0.5Mundo mais pesado, pulos curtos e secos
PULO-10(mais negativo) Salto de super-herói
✱
Curiosidade da indústria: nos clássicos de plataforma, times passavam MESES só afinando esses números — a física "gostosa" de controlar de certos jogos famosos é literalmente meia dúzia de constantes escolhidas com carinho obsessivo. A partir da missão do pulo, você vai poder afinar as suas.

🍎 Gravidade: o mundo puxa para baixo

A gravidade de jogo é DUAS linhas — e a ordem delas é a própria física:

Newton em Java
this.vy += Fisica.GRAVIDADE;   // 1. a força ACELERA (mexe na velocidade)
this.y += this.vy;             // 2. a velocidade MOVE (mexe na posição)

Frame 1: vy = 0.5. Frame 2: vy = 1.0. Frame 10: vy = 5... A queda fica cada vez mais rápida — aceleração de verdade, saída de duas linhas repetidas 60x/s. E quando ele pisa no chão, a engine (por enquanto) zera o vy e liga o noChao.

💡 O y cresce pra baixo, lembra?
Por isso a gravidade é vy AUMENTANDO (desce), e o pulo será um vy bem NEGATIVO (sobe). A placa mais importante do trânsito dos jogos 2D.

🧱 A missão mais "dev" do curso começa aqui

Até agora, a engine segurava o chão pra você com um truque simples (um chão plano fixo). Acabou a mordomia: neste módulo, VOCÊ escreve a colisão de verdade — a que permite plataformas flutuantes, paredes, buracos e degraus. É o código mais importante de qualquer plataforma, e o que separa quem "seguiu tutorial" de quem ENTENDE.

A ferramenta: Mundo.colide(x, y, larg, alt) — responde true se um retângulo naquela posição encosta em algum bloco #. A pergunta que sua lógica fará 60x/s: "se eu der este passo, vou entrar dentro de uma parede?"

a estratégia: tente → deu ruim? → desfaça
this.x += this.vx;                        // 1. dá o passo
if (Mundo.colide(this.x, this.y, L, A)) { // 2. entrou na parede?
    this.x -= this.vx;                    // 3. volta o passo. Parede venceu.
}
✱ Por que UM EIXO DE CADA VEZ
O segredo dos profissionais: resolver X e Y SEPARADOS. Se testar o movimento diagonal inteiro de uma vez, encostar no chão também travaria o andar (o teste acusaria colisão e desfaria TUDO). Separando: bateu na parede? Só o X desfaz — o Y continua caindo livre. Duas missões, um eixo cada.
🎉 Lição concluída!
Módulo 4 · Lição 2 de 5

📐 AABB: como máquinas percebem "encostou"

O nome pomposo — Axis-Aligned Bounding Box — esconde uma ideia de criança: cada coisa é um RETÂNGULO invisível, e dois retângulos se sobrepõem quando se sobrepõem NOS DOIS EIXOS ao mesmo tempo:

a pergunta dos 4 lados (é o que Mundo.colide faz por dentro)
sobrepoe = a.x < b.x + b.largura  // A começa antes de B terminar...
        && a.x + a.largura > b.x  // ...e termina depois de B começar (eixo X ✔)
        && a.y < b.y + b.altura   // mesma dança no eixo Y...
        && a.y + a.altura > b.y;  // ...✔ → ENCOSTOU!

É literalmente o && do Java Completo fazendo o trabalho pesado: quatro comparações, zero mistério. Praticamente todo jogo 2D da história — inclusive os que você ama — detecta colisões assim (e a engine checa os cantos do seu herói contra a grade de tiles, que é ainda mais barato).

💡 Por isso o herói é 24×28, não 32×32
Um herói mais MAGRO que o tile entra em passagens de 1 bloco sem raspar — conforto de controle clássico. Detalhes invisíveis assim são 90% do "esse jogo é gostoso".

⭐ Moedas: o contrato aoPegarMoeda

As moedas (C no mapa) são da engine: ela as desenha girando e detecta quando seu herói encosta (AABB de novo!). Ao encostar, ela chama um método SEU — se existir: aoPegarMoeda(). É o padrão profissional de callback: a engine avisa o evento; VOCÊ decide a consequência.

o contrato dos eventos do herói
void aoPegarMoeda() { ... }   // encostei numa moeda (ela já some sozinha)
void aoDerrotar()   { ... }   // pisei num inimigo (módulo 6)
void aoLevarDano()  { ... }   // um inimigo me pegou (módulo 6)
💡 Você já viu esse padrão duas vezes
No curso de HTML: onclick="..." — o navegador avisa o clique, você decide o que fazer. Na interface do Java Completo: o contrato de métodos prometidos. Eventos + contratos = como sistemas grandes conversam sem se conhecerem por dentro.

🖥️ O HUD: a interface por cima do mundo

Aquela barrinha ⭐ ❤️ ⏱ no canto do palco é o HUD (Heads-Up Display). Repare em dois segredos de como a engine o desenha:

SegredoPor quê
É desenhado POR ÚLTIMO no frameDesenho é como pintura: o que vem depois cobre o que veio antes. HUD por cima de tudo = HUD pintado no fim
Ignora a câmera (posição fixa na TELA)O mundo rola; o placar não. Coordenadas de MUNDO vs coordenadas de TELA — a distinção que todo dev de jogo carrega
Só LÊ seus campos (pontos, vidas)Você nunca "atualiza o placar" — ele exibe o estado. Interface reativa: o mesmo princípio dos frameworks web modernos
✱
Esse terceiro segredo merece moldura: o estado é a verdade; a tela é um espelho. No CORTEX, nos jogos, no React — sempre. Quando a interface "mente", o bug está em alguém editando o espelho em vez do estado.

👾 A IA do inimigo: 3 linhas de "inteligência"

Hora de ler código da engine — o inimigo vermelho patrulha com esta lógica, por frame:

a "IA" completa do patrulheiro (código real da engine)
inimigo.x += inimigo.vx;                       // 1. anda na direção atual
frente = (vx > 0) ? direita : esquerda;
if (Mundo.colide(frente) || !temChao(frente)) { // 2. parede à frente OU beirada?
    inimigo.vx *= -1;                          // 3. DÁ MEIA-VOLTA
}

Só isso. Anda; se vai bater ou CAIR, inverte. E no palco parece um bichinho "esperto" que patrulha a plataforma sem despencar. A lição valiosa: comportamento convincente ≠ código complexo — os goombas da história dos games são variações disso.

💡 O detalhe genial do "!temChao"
Checar se há chão UM PASSO À FRENTE é o que faz o inimigo respeitar beiradas. Tire mentalmente essa condição: ele cairia de toda plataforma. Uma negação booleana = a diferença entre patrulha e suicídio. 😄

💀 Game over, invencibilidade e o ciclo do desafio

Três mecânicas de "morte justa" que a engine implementa — e o raciocínio de design por trás:

MecânicaComoPor que existe
Invencibilidade pós-dano60 frames (1s) sem novo danoSem ela, encostar num inimigo drenaria as 3 vidas em 3 frames — punição dupla é a morte da diversão
Cair do mundoy passou do fim do mapa → respawn + vida a menosBuracos viram perigo REAL — e o level design ganha dentes
vidas == 0O loop para de atualizar; tela de GAME OVERRisco de verdade dá peso a cada pulo. Jogo sem derrota é passeio
✱ A régua do bom desafio

🎥 A câmera: o truque de mágica dos mundos grandes

Como um mundo de 2000px cabe numa tela de 640? Revelação: a câmera não existe. O que existe é desenhar tudo DESLOCADO:

a mágica inteira (código real da engine)
cam.x = heroi.x - larguraTela / 2;          // 1. "câmera" = herói no centro
cam.x = clamp(cam.x, 0, mundo - tela);      // 2. sem mostrar além das bordas

// 3. TUDO se desenha subtraindo a câmera:
g.ret(x - cam.x, y, ...);

O herói "anda pra frente"? Ilusão: na tela, ele fica quase parado no centro — é o MUNDO que desliza para trás. O clamp segura a câmera nas pontas (por isso, no comecinho da fase, o herói fica à esquerda e não no centro — repare nos clássicos: todos fazem isso!).

💡 Seu Pincel já sabia
Você desenhou o herói a curso inteiro em this.x sem pensar em câmera — porque o Pincel da engine desconta o cam.x por dentro. Abstração boa é isso: você escreveu código "de mundo" e ganhou código "de tela" de graça.

🗺️ Level design: as 5 regras de ouro

Fase boa não é sorte — é ofício. As cinco regras que os clássicos seguem religiosamente (e que você vai usar na sua fase):

RegraNa prática
1. Ensine sem palavrasO primeiro obstáculo é a versão FÁCIL do desafio da fase — o jogador aprende jogando, não lendo
2. Escale a pressãoMesmo desafio, apostas maiores: primeiro o pulo, depois o pulo sobre buraco, depois sobre buraco COM inimigo
3. Recompense a curiosidadeMoedas no alto/fora do caminho: quem explora, ganha — o caminho principal continua justo pra quem não
4. Respiro entre picosDepois de um trecho tenso, um corredor calmo. Tensão SEMPRE alta = dormência
5. O final é clímax, não pedágioO último trecho antes da bandeira usa TUDO que a fase ensinou, de uma vez
✱
Releia a fase da Missão 11 com esses óculos: degrau fácil → degrau duplo → moeda alta opcional → respiro → inimigo → bandeira. Não foi acaso. 😉 Agora projete a SUA com intenção — papel e lápis antes do teclado é o segredo dos level designers de verdade.

🔊 Sons e polimento: os 10% que parecem 90%

Percebeu os bipes? Moeda aguda (880Hz), pisão médio (660Hz), dano grave (180Hz), vitória festiva (1320Hz). A engine os sintetiza NA HORA com WebAudio — zero arquivos de som:

um bipe de fliperama em 5 linhas (código real da engine)
oscilador = audio.createOscillator();
oscilador.frequency.value = 880;      // agudo = feliz; grave = perigo
oscilador.type = 'square';            // onda quadrada = a voz dos 8-bits
oscilador.start();
oscilador.stop(agora + 0.09);         // 90 milissegundos e tchau

E o resto do polimento que você talvez nem notou conscientemente: a moeda PULSA (raio varia com o frame), o herói PISCA invencível, o quique do pisão, a sombrinha nos blocos. Nenhum muda as regras — todos mudam a SENSAÇÃO. A indústria chama de juice.

💡 A hierarquia do juice
Regra dos estúdios: primeiro o jogo FUNCIONA (módulos 1-7), depois ele COMUNICA (sons, flashes, tremidas). Juice em cima de jogo quebrado é maquiagem em bug. Você fez na ordem certa.
