🌍 O que é HTML? (e o que é um site, afinal?)

Respira. Vamos começar do zero absoluto, sem pressa. Todo site que você já visitou — banco, rede social, jornal — é, lá no fundo, um arquivo de texto. O navegador (Chrome, Safari...) lê esse texto e desenha a página na tela.

Esse texto é escrito em HTML: HyperText Markup Language, a "linguagem de marcação". Marcação = você pega um conteúdo e cola etiquetas nele dizendo O QUE ele é: "isso é um título", "isso é um parágrafo", "isso é uma foto".

a anatomia de uma etiqueta (tag)
<p>Olá, mundo!</p>
 ↑                    ↑
 abre a etiqueta      fecha a etiqueta (repare na barra /)

Leia em voz alta: "abre parágrafo... Olá, mundo!... fecha parágrafo". A tag de abertura e a de fechamento são um abraço em volta do conteúdo. Quase toda tag funciona assim.

✱
Prazer, sou o Prof. Asterisco — vou te acompanhar até o fim. Meu segredo pedagógico: HTML não se decora, se constrói. Por isso este curso tem três oficinas: código ao vivo pra mexer, lacunas pra completar e blocos pra montar. Mão na massa desde já!
💡 Curiosidade que acalma
HTML não tem "lógica difícil": não tem conta, não tem loop, não tem pegadinha matemática. É só aprender as etiquetas certas para cada coisa — tipo aprender o nome das ferramentas de uma caixa. Uma por vez, e a caixa é sua.

🏠 A página mínima: o esqueleto de TODO site

Toda página HTML do planeta — TODA — começa com o mesmo esqueleto de 4 peças:

o esqueleto sagrado
<!DOCTYPE html>          <!-- 1: aviso ao navegador: "isto é HTML moderno" -->
<html>                   <!-- 2: a caixa que embrulha TUDO -->
  <head>                 <-- 3: a CABEÇA: informações SOBRE a página -->
    <title>Meu site</title>
  </head>
  <body>                 <!-- 4: o CORPO: tudo que APARECE na tela -->
    <h1>Olá!</h1>
  </body>
</html>

Metáfora de casa: html é o terreno, head é a planta na parede (ninguém que visita vê, mas define tudo), body é a casa em si — onde as visitas entram.

💬 Comentários e organização: bilhetes para o futuro

Um comentário é um trecho que o navegador IGNORA completamente — é um bilhete de programador para programador (muitas vezes, de você para o você do futuro):

o bilhete invisível
<!-- Aqui começa o cardápio. Não mexer sem falar com a Ana! -->
<h2>Cardápio</h2>

Abre com <!-- e fecha com -->. Serve para explicar, para deixar lembretes e até para desligar temporariamente um pedaço da página sem apagar (os programadores chamam de "comentar o código").

E junto com comentários vem a indentação: aquele recuo que empurra o conteúdo para a direita quando está DENTRO de algo. O navegador não liga — mas seus olhos SIM. Código indentado é código que se lê como um mapa:

mesmos códigos, vidas diferentes
<!-- sofrível de ler: -->
<body><h1>Oi</h1><p>Tudo bem?</p></body>

<!-- um passeio: -->
<body>
  <h1>Oi</h1>
  <p>Tudo bem?</p>
</body>
✱
Hábito de profissional desde o dia 1: entrou dentro de uma tag, empurra pra direita. Daqui a 6 módulos, quando suas páginas tiverem 80 linhas, você vai agradecer de joelhos ao Wess do passado. 😄

💪 strong e em: dar peso às palavras

Para destacar palavras DENTRO do texto, as duas tags certas são:

TagSignificaVisual padrão
<strong>"Isto é IMPORTANTE"negrito
<em>"Leia com ênfase" (em = emphasis)itálico

Existem também <b> e <i>, que deixam negrito/itálico sem prometer importância — só visual. A diferença parece filosófica, mas é real: um leitor de tela para pessoas cegas dá entonação ao strong; o b ele lê no tom normal. HTML bom carrega significado, não só aparência.

📃 Listas: ul, ol e o li dentro delas

Lista é a primeira vez que você vê tags morando dentro de outras — o famoso aninhamento. A caixa de fora define o TIPO de lista; cada item é um <li> (list item) dentro:

as duas famílias
<ul>          <!-- Unordered: bolinhas, ordem não importa -->
  <li>Pão</li>
  <li>Leite</li>
</ul>

<ol>          <!-- Ordered: 1, 2, 3... a ordem IMPORTA -->
  <li>Misture</li>
  <li>Asse</li>
</ol>

Compras = ul (tanto faz a ordem). Receita = ol (assar antes de misturar termina em tragédia).

🧱 OFICINA DE BLOCOS: a lista de compras

Agora o jogo ganha caixas que abrem: o bloco ul é um contêiner — toque no espaço amarelo dentro dele e depois nos blocos li para encaixá-los lá dentro. Igualzinho ao aninhamento de verdade!

🔣 Caracteres especiais: como escrever < sem criar uma tag

Pense: se < SEMPRE abre uma tag... como escrever "2 < 5" num parágrafo sem o navegador achar que é código? Resposta: entidades — códigos que começam com & e terminam com ; e viram o caractere na tela:

Você digitaApareceNome
&lt;<less than (menor que)
&gt;>greater than (maior que)
&amp;&o próprio & (ampersand)
&nbsp;espaço que não quebragruda duas palavras na mesma linha
&copy;©copyright — chique no rodapé

✏️ Complete para a frase aparecer certa:

Queremos exibir na tela: 3 < 7 & 9 > 2 ©2026 (digite a entidade completa, com & e ;):

Os quadros de código DESTE curso usam &lt; e &gt; o tempo todo — é assim que te mostro tags sem o navegador executá-las. Agora você conhece o truque do mágico. 🎩

🔗 O link: a tag mais importante da internet

O "HT" de HTML é HyperText — texto com atalhos para outros textos. Sem o link, a web seria um monte de ilhas. Com ele, é uma teia. E ele apresenta um conceito novo: o atributo — uma informação extra DENTRO da tag de abertura:

anatomia do link
<a href="https://www.google.com">Ir para o Google</a>
     ↑ atributo = nome="valor", sempre na tag de ABERTURA

a = âncora; href = o destino. O texto entre as tags é o que fica clicável. Dois tipos de endereço:

TipoExemploQuando
Absolutohttps://google.comOutro site (endereço completo, com https)
Relativocursos.htmlPágina do SEU próprio site, na mesma pasta

🖼️ img: colocando imagens (e o sagrado alt)

A tag <img> é autossuficiente e vive de dois atributos:

a foto na parede
<img src="gato.jpg" alt="Gato laranja dormindo no sofá">

src (source) = onde a imagem mora — arquivo na sua pasta ou URL completa. E o alt? É a descrição alternativa, e ele NÃO é opcional de verdade. Três motivos:

1) Uma pessoa cega navega ouvindo — o leitor de tela lê o alt em voz alta. Sem ele: "imagem". Com ele: "gato laranja dormindo no sofá". 2) Se a imagem quebrar, o alt aparece no lugar. 3) O Google Imagens encontra sua foto pelo alt.

⚖️ Quando usar (e quando NUNCA usar) tabela

Tabela serve para dados tabulares: coisas que naturalmente têm linhas e colunas. Preços, horários, notas, comparações. Perfeito.

Mas houve uma era sombria (os anos 2000 🦖) em que se montava o LAYOUT inteiro do site com tabelas invisíveis — menu numa célula, conteúdo noutra... Isso morreu, e por bons motivos: quebra no celular, confunde leitores de tela e vira um pesadelo de manter. Layout é trabalho do CSS. Tabela é para dado, não para decoração.

SituaçãoTabela?
Horário das aulas da semana✅ Sim — é uma grade de dados
Comparar 3 planos e seus preços✅ Sim
Colocar o menu ao lado do conteúdo❌ Não — isso é layout (CSS)
Galeria de fotos em grade❌ Não — layout (CSS grid, no próximo curso!)
✱
Pergunta-teste que nunca falha: "faria sentido colocar isso numa planilha?" Se sim, tabela. Se você só quer "coisas lado a lado", é CSS chamando. Saber a ferramenta certa para cada serviço É a maturidade do ofício.

📋 form, input e label: a recepção do site

Até agora sua página só FALA. O formulário é quando ela escuta: nome, e-mail, respostas... Toda entrada de dados da web passa por aqui. As três peças fundadoras:

o trio inseparável
<form>
  <label for="nome">Seu nome:</label>
  <input type="text" id="nome">
</form>

form é o balcão; input é o campo; label é a plaquinha que diz o que escrever. E o casamento for="nome" ↔ id="nome" é sagrado: com ele, clicar na plaquinha foca o campo, e o leitor de tela anuncia o campo pelo nome certo. Formulário sem label é balcão sem placa.

🎖️ Atributos globais: id, class, title e data-*

Alguns atributos funcionam em QUALQUER tag — os globais. Os quatro grandes:

AtributoPapelRegra
idNome ÚNICO de um elementoUm por página — é CPF (âncoras, labels e o JavaScript dependem dele)
classEtiqueta de GRUPORepete à vontade; um elemento pode ter várias — é o gancho nº 1 do CSS
titleDica flutuante (tooltip)Aparece ao parar o mouse em cima
data-*Dados SEUS, invisíveisInvente o nome: data-preco="6.50" — o JavaScript lê depois
os quatro juntos num card de produto
<div id="produto-7" class="card destaque"
     title="Clique para detalhes" data-preco="6.50">
  Sonho de creme
</div>

Metáfora final da dupla mais importante: id = CPF (um só no país); class = profissão (milhares de padeiros). O CSS estiliza profissões; o JavaScript costuma procurar CPFs.

📱 A cabeça profissional: viewport, favicon e lang

Três linhas de head que separam um exercício de um site DE VERDADE:

o head de gente grande
<html lang="pt-BR">  <!-- o idioma da página (leitores de tela agradecem) -->
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <link rel="icon" href="favicon.png">
  <title>Padaria da Ana</title>
</head>

A linha do viewport merece tradução: "celular, use SUA largura real, sem fingir que é um desktop encolhido". Sem ela, seu site aparece minúsculo no telefone e a pessoa tem que dar zoom com dois dedos. Uma linha, e o site vira mobile.

✏️ Complete a cabeça profissional:

Idioma, tela do celular e o ícone da aba:
<html ="pt-BR">
<head>
  <meta name="" content="width=device-width, initial-scale=1.0">
  <link rel="" href="favicon.png">
</head>

🌍 Do playground para o mundo real: publique seu site

Até aqui, seu código viveu nos playgrounds da escola. Hora do rito de passagem: criar um arquivo de verdade, abrir no navegador de verdade, e colocar na internet de verdade. São três passos, e nenhum deles morde.

1️⃣ Criar o arquivo

Abra o Bloco de Notas (ou o VS Code, se já tiver). Escreva sua página — comece pela mínima, do Módulo 1. Salve como index.html: o nome importa (index = a porta de entrada que os servidores procuram) e a extensão .html é obrigatória. No Bloco de Notas, escolha "Salvar como" → Tipo: Todos os arquivos → nome index.html — senão ele salva um .txt disfarçado.

2️⃣ Abrir no navegador

Dois cliques no arquivo. Pronto: o navegador abre SEU site. Repare no endereço — começa com file:///, que significa "morando só neste computador". Edite o arquivo, salve (Ctrl+S), aperte F5 no navegador: a página atualiza. Esse vai-e-volta editor↔navegador é literalmente o dia a dia da profissão.

3️⃣ Publicar de graça no GitHub Pages

PassoOnde
Crie uma conta e um repositório (ex.: meu-site)github.com → New repository → Public
Suba seu arquivoAdd file → Upload files → arraste o index.html → Commit
Ligue o PagesSettings → Pages → Branch: main → Save
Espere ~2 min e visiteseunome.github.io/meu-site 🎉
